Seven safety habits, built into components.

Screens fail people under pressure in predictable ways. Each habit maps to a component you can drop into your app.

Read the principles

  • Fight alarm fatigue

    Group related signals, rate-limit repeats, and keep red for things that need a person now.

    StationGrid

  • One composite score

    Combine many weak signals into a single health score, with the factors one click away.

    HealthScore

  • Soft and hard limits

    Warn and ask for a reason past the usual range. Block outright past the safe one.

    LimitedNumberInput

  • Pause points

    Three to five checks before a risky action. Short enough to actually read.

    PausePoint

  • Confirm the target

    Before deleting, people type the exact name and see which environment they are in.

    ConfirmTarget

  • One timeline per entity

    Deploys, alerts, notes and changes in a single ordered record. No hunting across tabs.

    Timeline

  • Readable across the room

    A station density with large numerals for wall displays, sorted so the worst is top left.

    density="station"

# Pikore UI
> React + Tailwind v4 components for operational software.

## Rules
- Use severity or intent props, never raw colours.
- Destructive actions use <ConfirmTarget>.
- Risky actions use <PausePoint> (3–5 items).

## Components
- [Button](/docs/button.md): actions; one primary per view
- [HealthScore](/docs/health-score.md): composite 0–100
Prompt for your coding agent

Examples

Variants

Primary for the main action, secondary for alternatives, ghost for low-emphasis actions in toolbars.

<Button variant="primary">Save changes</Button>
<Button variant="secondary">Cancel</Button>
<Button variant="ghost">View history</Button>

Severity

Use severity only when the action itself carries risk. A critical button should almost always open a ConfirmTarget.

<Button severity="caution" iconStart={<CautionIcon />}>Restart service</Button>
<Button severity="critical" iconStart={<TrashIcon />}>Delete database</Button>

Sizes and states

Common mistakes

Deleting without confirming the target

Avoid
<Button severity="critical"
  onClick={deleteDb}>
  Delete
</Button>
Do this
<ConfirmTarget name={db.name}
  env="prod" onConfirm={deleteDb}>
  <Button severity="critical">
    Delete database
  </Button>
</ConfirmTarget>

Icon-only button with no name

Avoid
<Button variant="ghost">
  <TrashIcon />
</Button>
Do this
<IconButton label="Delete row"
  icon={<TrashIcon />} />

Notes for the developer

  

   
Spacing
A 4px base with steps at 4, 8, 12, 16, 20, 24, 32, 40, 48, 64. Controls use 12px horizontal padding and 8px gaps. Cards pad 16px. Page sections separate by 64px. Prefer the step below when unsure; density is calm because of alignment, not air.

   
Radius
control 8px for inputs, buttons and menu items. card 14px for cards, tables and tiles. Dialogs and the command palette use 16px; the landing monitor and page frames use 20 to 22px. Badges and switches are pills. Station tiles use 12px.

   
Shadows
Light mode leans on soft, layered shadows plus a hairline ring; dark mode leans on borders. shadow-1 for resting cards, shadow-2 for popovers, menus and tooltips, shadow-3 for dialogs, drawers, toasts and the palette. Dark mode uses deeper, blacker shadows because grey ones vanish on navy.

   
Motion
Durations 120ms (hover, colour), 180ms (switches, tabs, popovers), 280ms (dialogs, drawers), all on --ease-out. Motion only answers an action, with two exceptions: the hero trace draws once on load, and critical station tiles pulse slowly. prefers-reduced-motion sets every duration to 0 and stops both. Never animate numerals counting up; people read values mid-animation.

   
Focus ring
2px solid --ring with a 2px offset, using :focus-visible only. Text inputs use an inset version: border turns ring colour plus a 3px soft halo, so the ring doesn’t collide with neighbouring fields. Ring is teal in both themes and passes 3:1 against all surfaces.

   
Severity rules
  • Every severity indicator shows an icon or text label. Shapes: circle-check, circle-i, diamond, triangle, octagon.
  • Use -soft + -fg + -border for most surfaces; reserve solid fills for badges that must be seen from across a room and for destructive buttons.
  • Info is never used for a score. Accent is never used to mean status.

   
Typography
Instrument Sans for UI and prose: refined, slightly narrow, crisp at 12px and elegant at 76px with tight tracking. Azeret Mono for code and numerals: big metrics are set at weight 300 so they read calm and precise rather than loud, and stay tabular. Prose uses 1.65 line height and a 68ch measure; UI uses 1.35.

   
Intent aliases
primary = accent, secondary = neutral surfaces, success = normal, warning = caution, danger = critical. Info and advisory keep their names. Components accept intent or severity; both resolve to the same five tokens, so themes only define each colour once.

   
Tailwind v4 mapping
Expose tokens in @theme inline, for example --color-critical: var(--critical), --color-critical-soft: var(--critical-soft), --radius-card: var(--radius-card). Dark mode uses @custom-variant dark (&:where(.dark, .dark *)). Components read only these names, never raw hex.

VitalTile

Rules
Three to five items. Each item is something a person can verify in seconds, phrased as a fact rather than a question.
Items that the system can check itself are pre-filled with evidence (who approved, when). People confirm, they don’t re-do.
The action button names the action. After it runs, the toast uses the same word: Publish becomes Published.

Type the exact record name to delete it. The environment badge sits next to the name, so nobody deletes prod while thinking they’re in staging.

Names are case-sensitive.

     

     

   

   
Why typing works
Clicking Confirm is automatic; typing a name is not. The person has to read the target, and the environment badge sits right beside it.
Paste is allowed, but the match is exact and case-sensitive, so a near-miss like orders-prod-us never passes.
